# 摄像头强制检测（实验性）

## 行为与使用

开启设置中的「强制检测喝水」后，先露出面部定位一次，界面显示「嘴部位置已记住」后正常喝水。正式提醒会累计 1.2 秒有效杯具线索，随后自动完成并记录预设的一杯。杯子遮住面部时仍继续识别，不要求露出嘴巴、保持杯子与嘴巴之间的空隙或先放下杯子。较弱杯具线索结合手部辅助时按半速累计，理想情况下约需 2.4 秒，漏检时会更久。

嘴部位置在本次识别中保留，不因检测不到人脸而过期。杯具偶尔漏检只暂停进度，不回退。退出、重试或开始下一次提醒时重新定位并清零进度。

识别完成时先关闭摄像头并淡出全屏提醒，再在同一组屏幕上播放约 3 秒的透明矢量撒花。撒花不抢焦点、不拦截鼠标，也不会重复记水；减少动态效果时仅显示静态完成提示。普通动画预览和识别测试完成也可看见该效果，但不记水。

普通动画预览不访问摄像头。「测试摄像头识别（不记水）」会单独启动检测，识别完成或退出都不写入饮水记录，可用来检查角度和光线。首次使用需要 macOS 摄像头授权；拒绝、系统限制、没有设备、摄像头占用或中断时，界面提供说明与重试。

测试模式额外显示杯身 / 杯口 / 倾斜范围的杯具分数、主要分类名称和手部辅助状态。分数用于排查漏检，**不是识别准确率**；这些信息仅在本次会话内存中显示，普通正式提醒不显示，也不写日志。纸杯没有独立的 `paper_cup` 分类，使用系统通用 `cup` 类别，不能保证对每种纸杯都可靠。

强制提醒不接受点击确认、回车记水、延后或自动退场。紧急退出可以点击右上角并确认，或长按 Esc 2 秒；此路径不记录饮水。系统锁屏、睡眠、切换用户与显示器变化仍可中止提醒并关闭摄像头。识别测试可直接 Esc / 关闭退出。

摄像头检测当前默认关闭；已有偏好文件缺少新字段时也保持关闭，不会因升级而自动开启。关闭开关会立即中止当前识别并请求停止摄像头，本次不记录饮水。真实设备效果需要验证后再决定是否改变新安装的默认值。

## 实现

采集使用 AVFoundation，面部关键点使用 [VNDetectFaceLandmarksRequest](https://developer.apple.com/documentation/vision/vndetectfacelandmarksrequest)。`MouthPositionMemory` 保存最后一次可靠的嘴部坐标、脸宽与脸框；定位后每帧先检查这个位置附近的杯具，即使当前检测到的人脸数量为零也照常分类。

杯具已在附近时冻结嘴部坐标，避免被遮挡后的关键点移动识别区域；部分杯具分数达到 0.10 时也会保留坐标。没有足够杯具线索且仅有一张清晰人脸时，才用嘴唇和眼部关键点更新下一帧的坐标；残缺、明显缩短的脸框不能覆盖原位置。这里不再使用有时限的跟踪或丢脸宽限，坐标仅在新会话或显式重置时清除。

嘴部附近区域先由 Core Image 实际裁成独立图像，再交给系统内置 [VNClassifyImageRequest](https://developer.apple.com/documentation/vision/vnclassifyimagerequest)，无需下载第三方模型。`MouthRegion` 根据脸宽和画面宽高比提供三个互补范围：杯身及下方上下文、减少握杯手影响的杯口范围、覆盖向上倾斜杯身的范围。范围限制在图像内，并排除完全相同的裁剪；清晰杯具可提前结束本帧分类，避免总是运行三个范围。

`CupCameraWorker` 在 capture queue 配置 / 启停会话，在另一条 Vision queue 以最多约 6 fps 分析，避免从帧回调里阻塞停止会话。分类固定为 Revision 1，只接受实际查询到的杯具标识 `cup`、`mug`、`drinking_glass`、`bottle`、`jug`、`thermos`；不按子串匹配，因此 `cupcake`、`eyeglasses`、`thermostat` 和泛化的 `drink` 等不会当作杯具。

`DrinkingVesselEvidence` 保留最高及次高裁剪分数。最高分达到 0.22 时以正常速度累计；否则需要最高分至少 0.10、另一范围至少 0.06，且嘴边存在可靠手部关键点，才按半速累计。无杯具线索、只有单个较弱裁剪或仅有手都不能推进。没有把“手靠近嘴巴”单独当作喝水。

手部辅助使用 [VNDetectHumanHandPoseRequest](https://developer.apple.com/documentation/vision/vndetecthumanhandposerequest)，仅在上述较弱杯具条件满足时运行。检测最多两只手，只保留置信度至少 0.3 的关节点，同一只手至少三个点位于嘴部 / 杯具区域才提供辅助；远处桌面上的手不能提供辅助。它判断手的位置，不要求特定握法，也不是精确的握杯姿态分类器。

`DrinkGestureDetector` 只接收人脸数量、是否已记住嘴部、两个杯具分数与手部位置条件，不接收或保存图像。首次定位前不能通过；定位后不再以人脸是否可见作为进度条件。达到 `requiredEvidenceDuration`（1.2 秒加权有效时间）即完成，杯具或手部漏检保留已有进度。

大于 0.75 秒的帧空档不计入有效时间，但也不清掉进度；单帧最多计入 0.25 秒，避免卡顿直接补足识别时间。识别完成后状态锁定，不要求放下杯子。

`ReminderCompletionGate` 控制强制完成、延后和超时策略。`DrinkCameraVerifier` 在主 actor 发布状态，用 token 忽略过期回调，并在缺少画面、失败或退出时请求关闭会话。新 worker 创建新的嘴部记忆和进度。多屏共用一个 verifier、摄像头会话和完成状态，不会重复记水。

权限依据 [AVCaptureDevice.requestAccess](https://developer.apple.com/documentation/avfoundation/avcapturedevice/requestaccess(for:completionhandler:))。工程提供 `NSCameraUsageDescription` 和 `com.apple.security.device.camera` entitlement，不添加麦克风或网络权限。请求授权期间会降低提醒窗口级别，避免遮挡系统授权弹窗。

## 隐私与边界

画面、人脸 / 手部关键点、分类名称与线索分数仅在本机内存分析，不保存、录像或上传，不用于身份识别。正常模式与普通动画预览不会申请或开启摄像头。检测结束、提醒退出与会话不可用时停止采集。不要在日志、测试产物、截图或 Issue 中加入真实摄像头画面。

该方案是 **“记住的嘴边区域出现杯具”的启发式判断**，不能证实水已入口、液体类型、吞咽或实际毫升数。单目画面没有可靠深度信息，角度、透明杯、光线和背景都可能产生漏检 / 误检。长时间移开面部或离开座位后，旧位置仍可能被杯具触发；可退出后重新测试以重新定位。饮水量仍按用户的每杯容量记账。

## 验证

纯逻辑测试覆盖杯具出现即可完成、无需放下、初始定位门控、遮脸后继续累计、杯具漏检保留进度、空画面区域、低置信度、帧空档、旧时间戳、一次完成锁定、错误标签、嘴部区域边界和完成门控。它们验证程序约束，不代表识别模型在真实场景中的准确率。

回归测试专门覆盖“正常喝水挡住整张脸仍能完成”“丢脸很久后位置仍可用”“丢脸或杯具漏检时进度不回退”，以及清晰人脸移动 / 缩放、残缺脸框拒绝和显式重置。实际摄像头对不同杯子的改善程度仍需复测。

纸杯 / 无柄杯优化新增裁剪覆盖、避开下方握杯手、向上倾斜范围、手部位置边界、多处较弱杯具线索、半速累计、空手拒绝和辅助丢失不回退测试。它们使用几何和分数序列，不代表已经用真实纸杯测出了成功率；仍需持普通纸杯正常喝水复测。

实际摄像头授权、设备占用、不同杯子、光线和角度需要维护者通过「测试摄像头识别」验证。本次开发不自动开启真实摄像头，也没有保存真实摄像头测试素材。详细状态见 [验证记录](VALIDATION.md)。
