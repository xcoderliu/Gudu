工程迁移到 Documents 后完成了 Debug 与 Release 构建。检测时间改为 1.2 秒后，60 项核心测试通过；固定骨骼长度与连续性测试仍逐帧覆盖整段动作。Release 产物包含 arm64 与 x86_64；Intel 硬件运行仍需实际验证。Debug 本地 ad-hoc 签名通过 `codesign --verify --deep --strict` 检查，两个音频资源均打包在应用中。默认本地签名为 ad-hoc；Xcode 会提示这种签名下关闭 Hardened Runtime，不表示已经完成 Developer ID 分发。

`./scripts/smoke_test.sh` 应用状态集成检查通过：使用独立的临时 UserDefaults，运行真实 1 分钟 Timer，确认自动触发，再检查 5 分钟延后与暂停。同时验证了关闭检测开关触发清理回调、预览不改变计划 / 不记水、记录 / 撤销行为。检查不打开提醒窗口，不改动真实数据。

`./scripts/check_completion.sh` 通过：在 3 块屏幕上创建隐藏的原生窗口，通过实际视图完成回调验证全屏先关闭、透明撒花不抢焦点 / 鼠标、多屏同一时间源、3 秒后清理、重复完成只记一次、预览不记水、不改变计划、新提醒清除撒花、延后不撒花，以及系统中断取消装饰但保留已经确认的一杯。未显示窗口、播放声音或启动摄像头；真实桌面上的视觉效果与鼠标操作仍需人工检查。

撒花使用实际矢量视图离线导出动态 GIF、透明 PNG 与减少动态效果的静态提示进行检查。透明图角落 alpha 为 0，静态提示没有粒子；新版为双侧全屏喷发加上方飘落，替换了覆盖偏小的两束效果。GIF 只叠加示意渐变背景，不读取桌面。

## 界面与素材检查

已在运行的应用中检查主界面、提醒设置、饮水记录与撤销、间隔预设、跟随鼠标模式、所有屏幕模式、预览、Esc 退出、预览完成和自动退场。预览完成后没有增加饮水记录。

新版人物形象分组选项、工作屏幕选项、声音开关已在运行界面中显示。开放式厨房场景以及中性 / 女性 / 男性的接水、倾斜喝水与放松姿态，使用应用同一套矢量代码导出后进行了视觉检查；配图使用隔离的示例数据，不包含真实饮水记录。

摄像头功能的设置界面与强制提醒界面使用源视图进行了离线渲染检查，没有启动真实摄像头或保存真实画面。Vision Revision 1 的杯具标签通过系统 API 查询确认。纯逻辑测试不等同于真实识别准确率；授权弹窗、摄像头占用、透明杯、不同光线和角度尚需通过「测试摄像头识别」实测。因此当前版本保留默认关闭。

用户实测反馈旧版存在“杯子在脸旁易通过、正常喝水遮挡面部反而漏检”，并进一步指出丢失人脸时进度仍会回退。本次按反馈改为保留最后一次可靠嘴部位置，取消丢脸超时，并使杯具漏检只暂停进度；同时实际裁出附近区域后再分类。新版真实摄像头准确率仍待用户复测，未将逻辑测试当作准确率证明。

音频资源已确认是可读取的 PCM WAV，主音轨 15 秒、完成声 1.1 秒。音效来自项目的离线合成脚本。听感、个人舒适音量和长时间重复播放体验仍建议维护者实际试听调整。

界面自动化在部分操作中返回了窗口不可用或界面变化，未把这些结果认定为用户主动中断；因此没有把未完成的窗口触发观察、硬件逐屏确认或系统场景检查标为通过。实际 Timer 与状态流已通过上述独立集成检查。
